# Plan for #5: Enable metrics endpoint in deployment

## Goal
Operations can scrape runtime metrics from the deployed app; the app stays otherwise unchanged while the metrics listener is enabled and documented.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- Confirmed: `k8s/configmap.yaml` sets `METRICS_ENABLED` and `METRICS_PORT`; change: yes.
- Confirmed: `k8s/deployment.yaml` exposes the container ports and mounts the config; change: yes.
- Confirmed: `k8s/service.yaml` exposes service ports; change: yes.
- Confirmed: `README.md` documents runtime configuration and how to access the metrics endpoint; change: yes.
- Confirmed: `src/config.ts` requires `METRICS_PORT` when `METRICS_ENABLED=true`; change: no.
- Confirmed: `src/server.ts` starts a plain-text metrics listener when enabled; change: no.
- Open: none.

## Tests
- `npm run verify` for local sanity, then pipeline rollout/smoke checks for the deployment.

## Environment contract
- This change requires `METRICS_ENABLED=true` and `METRICS_PORT=9100` in `k8s/configmap.yaml`; `src/config.ts` already defines both and rejects invalid values.

## Risks
- A missing or invalid `METRICS_PORT` crashes the pod at startup and fails rollout/stability/smoke.
- Exposing the wrong service or container port breaks scraping and makes the deployment appear unhealthy.

## Open questions
1. None.

## Decisions
- No additional decision needed; the issue is explicit and the code already supports the metrics listener.
