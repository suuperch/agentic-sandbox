# Plan for #3: Add DELETE /api/runs/:id

## Goal
Users and test tooling can delete a recorded run through `DELETE /api/runs/:id`; successful deletion returns 204 and removes the run from subsequent listings. Existing reads, creates, validation, and the web page remain unchanged, while unknown IDs return 404 and `running` runs are protected with 409.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- Confirmed: `src/runs.ts` `RunStore` owns the in-memory map and exposes `get`; add deletion/protection behavior here: change yes.
- Confirmed: `src/app.ts` `createApp` defines run routes and the documented 404 error shape; add the DELETE route and 404/409 responses: change yes.
- Confirmed: `test/app.test.ts` uses a fresh `RunStore` per test and supertest; add success, unknown ID, and `running` protection cases: change yes.
- Confirmed: `README.md` API table documents existing run endpoints and error shapes; document DELETE and its errors: change yes.
- Plausible: `public/index.html` has no delete control or API call; no UI change is required unless product scope expands: change no.
- Confirmed: `src/config.ts` and `k8s/configmap.yaml` contain only runtime configuration, unrelated to deletion: change no.
- Confirmed: `e2e/smoke.spec.ts` covers health and create UI flows, not deletion: change no.

## Tests
- `test/app.test.ts`: delete a planned run, assert 204 with no response body and absence from `GET /api/runs`; assert unknown ID returns 404 with `{ error: "run not found", id }`; create a run, set its returned status to `running` for the fixture, and assert 409 with `{ error: "run is in progress" }`.

## Environment contract
- No environment variables are added or changed; no updates to `src/config.ts`, `k8s/configmap.yaml`, or the README environment table.

## Risks
- Deleting from the store must not leave the run visible through `list` or alter unrelated IDs.
- The status guard must reject only `running`; `planned` and `done` should remain deletable.
- The route must be registered with the existing `/api/runs/:id` family and preserve JSON error shapes while returning an empty 204 response.
- Pipeline risks are limited to unit-test/type-check failures and browser/deploy smoke regressions caused by an unintended route or store change; rollout and stability should be unaffected.
